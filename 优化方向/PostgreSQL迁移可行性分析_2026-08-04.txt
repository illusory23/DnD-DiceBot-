1.4  数据规模评估

  当前 240KB，总行数约 600 行。属于微型数据库。
  即使增长 1000 倍（1000个用户 × 20个角色 × 完整数据），也仅约 240MB。
  PostgreSQL 对此规模完全无压力。

三、两条迁移路径对比
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

┌──────────────────┬─────────────────────────────────┬─────────────────────────────────┐
│                    │ 路径A: psycopg2 原生SQL             │ 路径B: SQLAlchemy ORM (推荐)      │
├──────────────────┼─────────────────────────────────┼─────────────────────────────────┤
│ 改动量             │ 中等 (~300行)                    │ 大 (~800行，52个函数重写)         │
│ 学习曲线           │ 低（和 sqlite3 用法相似）         │ 中（需要学习ORM概念）             │
│ 类型安全           │ 低（字符串SQL，无编译检查）        │ 高（模型定义即类型声明）           │
│ 数据库切换          │ 低（仍耦合 SQL 方言）            │ 高（改连接串即可切换MySQL等）      │
│ 迁移工具           │ 手写 SQL                        │ Alembic 自动迁移                  │
│ 连接池             │ 需手动配置 psycopg2 pool         │ SQLAlchemy 内置连接池              │
│ 事务管理           │ 手动 commit/rollback            │ Session 自动管理                   │
│ 性能               │ 高（最薄抽象层）                 │ 高（略有开销，可忽略）             │
│ 与现有代码兼容       │ 改 SQL 语法 + 占位符即可         │ 需要完整重写所有数据库操作          │
│ 长期维护成本        │ 高（SQL字符串散落各处）           │ 低（模型集中、迁移可追溯）          │
│ 推荐度             │ ★★★ (快速方案)                   │ ★★★★★ (正确方案)                   │
└──────────────────┴─────────────────────────────────┴─────────────────────────────────┘

  推荐路径B（SQLAlchemy ORM），原因:
    ① flask-sqlalchemy 已在 requirements.txt 中，升级依赖零成本
    ② 项目已有 52 个数据库函数，未来还会增长——ORM 让新增字段/表变得轻松
    ③ Alembic 自动迁移替代手写的 _migrate_schema()，不再需要 PRAGMA 黑魔法
    ④ 类型安全 + IDE 智能提示（如果用 Type Hints）

4.3  SQLAlchemy 模型设计

```python
# core/models.py — 模型定义示例

from flask_sqlalchemy import SQLAlchemy
from sqlalchemy import Column, Integer, String, Boolean, Float, Text, DateTime, ForeignKey
from sqlalchemy.orm import relationship

db = SQLAlchemy()

class Character(db.Model):
    __tablename__ = 'characters'

    id            = Column(Integer, primary_key=True, autoincrement=True)
    name          = Column(String(100), nullable=False)
    player        = Column(String(100), default='')
    created_by    = Column(String(100), default='')
    level         = Column(Integer, default=1)
    class_        = Column('class', String(50), default='')
    race          = Column(String(50), default='')
    # ... 28 个字段
    group_id      = Column(Integer, ForeignKey('character_groups.id', ondelete='SET NULL'))

    # 关系（自动联表查询）
    abilities     = relationship('Ability', back_populates='character',
                                  cascade='all, delete-orphan', uselist=False)
    skills        = relationship('SkillProficiency', back_populates='character',
                                  cascade='all, delete-orphan')
    weapons       = relationship('Weapon', back_populates='character',
                                  cascade='all, delete-orphan')
    inventory     = relationship('InventoryItem', back_populates='character',
                                  cascade='all, delete-orphan')
    # ... 等
```

  关键收益:
    • `character.abilities.str` 代替 `cursor.execute("SELECT * FROM abilities WHERE...")`
    • `db.session.delete(char)` 自动级联删除 10+ 张关联表（不再手动逐表删除）
    • 新增字段只需改 model + 一条 alembic 命令

```python
    'postgresql://dicebot:dicebot_password@localhost:5432/dicebot_db'

SQLITE_URL = 'sqlite:///data/characters.db'
```

```python
# core/database.py
from flask import Flask
from flask_sqlalchemy import SQLAlchemy
from config import DATABASE_URL

db = SQLAlchemy()

def init_app(app: Flask):
    app.config['SQLALCHEMY_DATABASE_URI'] = DATABASE_URL
    app.config['SQLALCHEMY_TRACK_MODIFICATIONS'] = False
    app.config['SQLALCHEMY_ENGINE_OPTIONS'] = {
        'pool_size': 5,           # 连接池大小
        'pool_recycle': 3600,     # 1小时回收
        'pool_pre_ping': True,    # 连接前检查有效性
    }
    db.init_app(app)
```

十一、不做 PostgreSQL 的替代方案
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  如果暂时不迁移数据库，可以先做「SQLite + ORM」过渡:

    方案: 先引入 SQLAlchemy ORM，但仍使用 SQLite 作为后端
    收益:
      • 52个函数改为 ORM 风格，代码大幅简化
      • Alembic 自动迁移，告别 PRAGMA 黑魔法
      • 未来切换 PostgreSQL 只需改一行连接字符串
    成本: 3天（阶段3的工作量不变，但跳过了 PG 部署和数据迁移）
    推荐: ⭐⭐⭐⭐ (如果暂时不想运维 PG，先走这条路)
