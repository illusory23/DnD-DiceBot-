2.3  当前问题

  ⚠ 图层图片的 dataURL（base64）极其巨大:
     • 5000×5000 PNG → 原始约 25MB → base64 约 33MB
     • 一个图层就超出 localStorage 5MB 限制
     • 所以 _light 备份只能剔除 >200KB 的 dataURL

  ⚠ 服务端图层文件可能丢失（如本次 5.png 404 问题）:
     • url 引用 `/maps/layers/5.png` 但文件已被删除
     • 没有 dataURL 兜底时图层永久丢失

  ⚠ 缺少一键导出/导入 UI:
     • uploadSaveToResource() 已实现但藏在资源库面板里
     • 没有直接的文件下载按钮

3.2  图层图片策略

  ┌─────────────────────┬──────────────────────────────────────────────────────┐
  │ 策略                  │ 说明                                                  │
  ├─────────────────────┼──────────────────────────────────────────────────────┤
  │ dataURL 优先          │ 完整的 base64 图片，自包含、永不丢失                   │
  │ url 作为备用           │ 服务端路径，dataURL 损坏时可尝试加载                    │
  │ 文件体积              │ 一个 5000×5000 图层: JSON 约 33MB (base64)            │
  │                      │ 实际 PNG 压缩后约 1-3MB (取决于内容复杂度)              │
  │                      │ 带 3 个图层的存档: 约 5-15MB                          │
  └─────────────────────┴──────────────────────────────────────────────────────┘

3.3  压缩优化（可选）

  方案A: 纯 JSON（最简单）
    JSON.stringify(state) → 直接下载 .json 文件
    优点: 实现简单、人类可读 meta 部分
    缺点: base64 膨胀 33%，文件体积大

  方案B: JSON + 独立图片文件（ZIP包）
    → 图层图片存为独立 .png 文件
    → 打包为 .zip
    优点: 无 base64 膨胀，文件更小
    缺点: 需要 JSZip 库，实现复杂

  方案C: 混合方案（推荐）
    → JSON 文件存 meta + 非图层数据
    → 图层 dataURL 保留在 JSON 中
    → 增加导出选项: "紧凑模式" (url only) / "完整模式" (含 dataURL)
    优点: 灵活、兼容两种场景
    缺点: 需要两种导出逻辑

4.2  代码实现（核心函数）

```javascript
// ━━━ 导出地图为 JSON 文件 ━━━
function exportMapAsJSON(includeDataURLs = true) {
    var state = collectState();

    // 清理损坏图层
    state.layers = state.layers.filter(function(l) {
        return l.dataURL || l.url;
    });

    // 紧凑模式：移除 dataURL
    if (!includeDataURLs) {
        state.layers = state.layers.map(function(l) {
            return { ...l, dataURL: '' };
        });
    }

    // 添加元数据
    state._meta = {
        version: 2,
        app: '尘封之卷',
        exportTime: new Date().toISOString(),
        layerCount: state.layers.length,
        strokeCount: state.brushStrokes.length,
        tokenCount: state.mapTokens.length,
    };

    // 触发生成和下载
    var json = JSON.stringify(state, null, 2);
    var blob = new Blob([json], { type: 'application/json' });
    var url = URL.createObjectURL(blob);
    var a = document.createElement('a');
    a.href = url;
    a.download = '尘封之卷_地图_' + new Date().toISOString().slice(0,10) + '.json';
    a.click();
    URL.revokeObjectURL(url);

    Toast.success('地图已导出 (' + (blob.size/1024/1024).toFixed(1) + ' MB)');
}

// ━━━ 从 JSON 文件导入地图 ━━━
function importMapFromJSON(file) {
    var reader = new FileReader();
    reader.onload = function(e) {
        try {
            var state = JSON.parse(e.target.result);

            // 校验格式
            if (!state.brushStrokes && !state.layers) {
                throw new Error('无效的存档文件：缺少必要数据');
            }

            // 版本兼容处理
            if (state._meta && state._meta.version === 1) {
                // v1 → v2 迁移逻辑
            }

            // 应用到画布
            applyState(state).then(function() {
                saveState();
                Toast.success('地图已导入 (' +
                    (state.layers||[]).length + ' 图层, ' +
                    (state.brushStrokes||[]).length + ' 笔画)');
            });
        } catch(err) {
            Toast.error('导入失败: ' + err.message);
        }
    };
    reader.readAsText(file);
}
```

  实测数据（基于当前 shared_canvas.json + maps/layers/1.png）:

  ┌──────────────────────┬──────────┬──────────────────────────────────────────┐
  │ 内容                  │ 体积      │ 占比                                     │
  ├──────────────────────┼──────────┼──────────────────────────────────────────┤
  │ 图层图片 (1张, base64) │ ~1.8MB   │ 99%                                      │
  │ 笔画 (156条)          │ ~15KB    │ <1%                                       │
  │ 文字/标记/迷雾/状态    │ ~2KB     │ <1%                                       │
  │ │ 元数据              │ ~0.5KB   │ <1%                                       │
  ├──────────────────────┼──────────┼──────────────────────────────────────────┤
  │ 总计 (1个图层)         │ ~1.8MB   │                                           │
  │ 总计 (3个图层)         │ ~5-8MB   │                                           │
  │ 总计 (10个图层)        │ ~15-30MB │                                           │
  └──────────────────────┴──────────┴──────────────────────────────────────────┘

  结论: 图层图片是 JSON 体积的绝对主导因素。
        紧凑模式（仅 URL）的 JSON 仅 ~20-50KB，但依赖服务端文件。
        完整模式（含 dataURL）自包含但体积大。

  建议: 默认导出完整模式（自包含、安全），同时提供紧凑模式（方便快速备份）。
