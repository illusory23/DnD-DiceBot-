# 尘封之卷-九子的注视（跑团平台）

D&D 5e 跑团平台项目说明，供 AI 与维护者快速了解结构，避免误改。

## 项目结构

- `骰娘/`：平台主体（QQ 骰娘机器人 + 跑团官网）
- `尘封之卷词条编写网站/`：词条卡网站（独立子项目）
- `其他参考资料/`、`跑团1-4/`、`杂记与相关设定/` 等：设定、模组与参考资料

## 技术

- 后端：Python 3 + Flask + SQLAlchemy ORM
- 数据库：PostgreSQL（2026-08-15 已迁移，`config.py` 中 DATABASE_URL 可覆盖回 SQLite）
- 前端：原生 HTML / CSS / JavaScript（无框架），Three.js 3D 骰子
- 机器人：`dnd_bot.py`（QQ 骰娘）

## 核心文件

- `骰娘/dnd_bot.py`：QQ 骰娘主程序（角色卡指令、掷骰、法术位管理）
- `骰娘/web/app.py`：官网 Flask 后端（API + 页面路由，单文件较大）
- `骰娘/core/models.py`：SQLAlchemy 数据模型
- `骰娘/core/character.py`：角色卡业务逻辑（属性/技能/法术/物品/背景）
- `骰娘/core/dnd5e_rules.py`：D&D 5e 规则数据（法术位表等）
- `骰娘/utils/excel_importer.py`：Excel 角色卡导入（多模板适配）
- `骰娘/web/templates/*.html`：页面模板
- `骰娘/web/static/*.js`：前端逻辑（按模块拆分）
- `骰娘/config.py`：数据库 / 端口等配置

## 修改规则

- 不要重构已有系统，改动保持最小化
- 修改前检查调用关系：前端函数常跨文件暴露到 `window`，后端接口有多个调用方
- 保留原有数据结构：API 字段、数据库列名、localStorage/WS 消息格式不可随意更改
- 每次修改骰娘代码后，在 `骰娘/更新日志/` 新建 `YYYY-MM-DD_序号_主题.txt` 记录问题、根因、修复与验证
- 修改静态资源（js/css）时同步更新模板中的缓存版本号（如 map.html 的 `v=60`）
- 后端 `make_server` 启动无自动重载，改后端代码需重启服务才生效
- 大改前可参考 `骰娘/backups/` 中的历史版本（按日期归档）

## 战斗规则（D&D 5e）

- d20 攻击检定：d20 + 熟练加值 + 属性调整值 vs AC
- AC 判定：检定结果 ≥ 目标 AC 即命中
- 优势/劣势：掷 2 个 d20 取高值/低值
- 伤害：武器伤害骰 + 属性调整值
- 法术位：1-9 环，每环有最大数量与已用数量，长休恢复

## 数据库要点

- 核心表：`characters`、`learned_spells`、`spell_slots`、`weapons`、`inventory_items`、`background_details` 等（见 `core/models.py`）
- 前端期望 `spell_slots` 格式：`{环阶: {max: 最大数, used: 已用数}}`
- 角色可通过 id 或名字解析（`_resolve_char`），API 路径形如 `/api/character/<name_or_id>/...`
