## 功能

- **白板绘图**：画笔/形状绘制、框选移动、文字框，可随时清除
- **token**：放置角色/怪物 token，拖拽、旋转、按角色同步 HP；他人 token 头像与名称均可见，仅角色信息面板不可查看；DM 公开角色可见
- **战争迷雾**：画笔式涂抹遮蔽、橡皮像素级挖洞、洪水填充；DM 半透明 / PL 不透明；每笔雾与擦除轨迹独立 id/粗细，WS 增量同步
- **图层**：图片图层（外置存储到 `maps/layers/`），可切换显隐
- **内嵌战斗面板**：添加战斗者、先攻排序、回合轮转、伤害/治疗、状态标记；战斗中临时加入按先攻排队、本轮不插队；独立战斗页（combat.html）同套规则；**先攻平手规则（v5.7）**：先攻相同时比较敏捷调整值 `dexMod`，调整值高者优先（添加参战者时从角色缓存计算记录，开始战斗与临时加入重排两处排序均生效，无 dexMod 旧数据按 0 兜底）
- **战斗轮死亡豁免（v5.9 + v5.10 体质调整值）**：轮转到倒地角色（`hp≤0` 且未死亡）时自动触发 `maybeTriggerDeathSave`——GET 角色查 `death_saves`（is_stable 稳定/已死亡则跳过，已死亡补同步 token 黑白）→ 复用 d3d 3D 覆盖层（dice-engine-v3 与 /dice3d 同引擎）死亡豁免专用模式（`setD3dDeathSaveMode` 改标题"💀 死亡豁免：xxx"；`roll3dStage('d20', null, '🎲 掷死亡豁免')` 保留按钮文案）→ 物理动画 → `POST /api/character/<id>/death-save` 判定 → 结果弹窗；**v5.10 规则修复**：掷骰后从角色数据提取体质调整值（`deathSaveConMod`：ability_mods.con 优先，回退 abilities 计算）随 `{roll_value, modifier}` 一并上报，弹窗/播报显示完整加值（`fmtDeathSaveTotal`："8+3=11"，无加值保持"8"）；**自然 1/20 判定改用原始骰值**（`roll===1`/`roll===20`，修复加值后 total 误判：roll18+2=20 误判稳定、roll1+3=4 漏判大失败）；**聊天室播报全覆盖**：成功"💀 xxx 死亡豁免成功（8+3=11），成功 x/3"、失败"…失败（…），失败 x/3"、大失败 1"…掷出 1（大失败）！失败 ×2（x/3）"、稳定"…稳定下来！"、死亡"💀 xxx 失血过多，无力支撑，宣告死亡..."；**失败 3 次死亡**：`combatant.dead=true` + token 黑白化（`applyTokenDeadStyle`：`filter:grayscale(1)` + WS tokens 增量同步）+ `pushCombatState`；掷后 `fetchCharData` 刷新缓存并重渲染选中的 token 信息面板（死亡豁免次数实时可见）；**上报健壮性**：`resp.ok` 检查 + json try-catch + 原始骰值 1-20 校验，失败时 alert 明确提示（不再静默）；触发点：mapStartCombat（首轮首位倒地）+ mapNextCombatant（正常轮转与新回合回绕两分支），`deathSaveBusy` 防并发，取消掷骰下次轮到再触发
- **token 信息面板（v5.9 增强）**：`showTokenInfoPanel` 新增显示——死亡豁免行（成功 x/3 | 失败 x/3 + [稳定]/[死亡] 标记，无记录不显示）、AC 行追加 ✨ 法术DC（spell_save_dc）与 👁️ 被动察觉（passive_perception）；**打开时自动强制刷新**（`fetchCharData(charId, true)` 绕过缓存，`_panelRefreshing` 防重入，刷新后仍选中则重渲染）

## 关键数据结构

- **战斗**：`{combatants:[{name, initiative, initDetail, hp, hpMax, ac, conditions[], charId, **dexMod**（v5.7 敏捷调整值，先攻平手比较用）, isCurrent, joinedLate, addedBy, addedByRole, **dead**（v5.9 死亡豁免失败 3 次 → true，防重复触发+列表 💀 标记，applyRemoteCombatState 整体替换保留）}], round, _ts, started}`；localStorage `dnd_combat_state`（map.js 与 combat.js 共用）；服务端 PG `combat_state` 表
- **token 数据（v5.9）**：`tokenNetData` 含 `dead` 字段（`!!t.dead`），WS tokens 增量同步；创建/合并时 `filter:grayscale(1)` 黑白化（createMapTokenElement 第 10 参、mergeRemoteTokens 已有 token 同步更新样式）
- **迷雾**：`fogStrokes`/`fogErasures`（每笔带 id/width/radius）/`fogVisible`；同步格式 `{strokes, erasures, visible}`，兼容旧列表/polygons/layers 格式
- **地图存档**：IndexedDB `dnd_map_db`/`map_states`（键 `dnd_map_state`、`dnd_map_state_<slotId>`）；localStorage 键 `dnd_map_state`（旧）、`_light`（≤200KB）、`_unload`、`_emergency`、`dnd_map_slots`；服务器存档 `跑团存档/地图/<name>.json`（自动存档 `_autosave`）
- 房间身份：sessionStorage `dnd_joined_room`

## 修改注意点（已知坑）

1. **时间戳版本保护**：POST/WS 均校验 `_ts`，旧状态拒绝（409 / `combat_update_conflict`），`_force` 可强制覆盖（清空场景）；前端冲突后先合并本地 3 秒内编辑再重推
2. **WS 半开降级**：`pushCombatState` WS 推送带 `_cid`，1.5 秒无 ack 自动降级 HTTP；3 秒轮询始终保留兜底
3. **空状态判断**：后端必须用 `'combatants' in state`，空数组不能当 falsy（否则清空被吞、状态回弹）
4. **作用域坑**：`_dirtyFlags`/`_pushDebounce`/`_pushInFlight`、`tokenNetData`/`textNetData` 必须留在顶层作用域（曾因声明在 boot IIFE 内导致 ReferenceError、token 旋转卡死）
5. **token 隐私**：他人 token 名称与头像均可见（`refreshTokenPrivacy` 不做显示层脱敏）；隐私拦截仅在 `canViewCharInfo`（含 `is_public`）——PL 点击他人 token 不显示角色信息面板；**v5.7 起选中先于移动权限检查**（mousedown 先 `selectElement` 再 `ensureTokenCharData`），PL 可选中他人 token 显示攻击/治疗按钮，仅拖动/缩放/删除被权限拦截
6. **迷雾半径**：每笔雾保存自身 `width`、擦除轨迹保存自身 `radius`（否则远程端粗细不对）；擦除为像素级挖洞，遮盖判定需排除洞内探针点
7. **缓存版本号**：改 map.js 等必须同步 bump map.html 的 `v=N`（当前 map.js v83 / map-page.js v77，v5.10）；改 combat.js/combat-monsters.js 同步 combat.html `v=35`（v5.8）
8. 后端 `make_server` 无热重载，改后端代码需重启服务
9. 地图存档保存失败日志为 `[Errno 22] Invalid argument`（`跑团存档/地图/_autosave.json`）——曾出现，注意该目录写入权限
10. **攻击/治疗选择弹窗**（v5.3）：`attack-picker-popup`/`heal-picker-popup` 复用 `.attack-popup` 样式类；攻击者/治疗者列表与侧边栏同源（`/api/characters?name=&role=`；**v5.10 起不再排除目标 token**——可选自身，filter 仅保留 `c && c.id`）；`pickAttackSource` 的 `sourceName`（纯名称）与 `sourceLabel`（"武器 · xx"）分开——播报用 sourceName，弹窗显示用 sourceLabel
11. **伤害三字段**（v5.3）：`parseDmgDice` 解析出的面数若不在 d4-d100 选项内（如 d3），保留手动值不覆盖；曾因 damageRoll 引用已删除的 `config` 变量导致点击掷骰无反应（ReferenceError）——改掷骰函数时注意表达式构建统一走 `buildDamageExpr`
12. **播报上下文**（v5.3）：damageRoll 播报读 `attackCtx.attackerName/sourceName`，healRoll 播报读 `healCtx.healerName/sourceName`；自由攻击/治疗时字段为空，播报回退"攻击 击中了…/治疗，…"
13. **死亡豁免触发**（v5.9）：只在战斗操作端触发（DM 点"开始/下一位"）；PL 只读端不弹 3D 界面，死亡结果经 WS tokens op（token 黑白）与 combat_update（combatant.dead）同步；`maybeTriggerDeathSave` 内部查角色 API（is_stable 稳定角色跳过），有 `deathSaveBusy` 防并发，勿在轮转同步回放路径重复调用；死亡豁免 3D 复用 d3d 覆盖层，`setD3dDeathSaveMode` 改标题/按钮文案，结束必须 `setD3dNormalMode` 恢复
