## 文件与职责（web/ 下）

- `templates/north-expedition.html`（约 645 行）：单页容器，按序引入 data → main → **camp** → survival → guild → tavern → fx（约 617-622 行）；冒险者面板头部含头像元素 `#advAvatar` + 隐藏文件输入 `#advAvatarInput`
- `static/north-main.js`（约 4900 行）：核心引擎（事件链/存档/营地书页/UI/冒险者头像/角色锁定/**useBackpackItem 物品使用 + refreshBagUseUI，v5.4**）
- `static/north-camp.js`（约 1320 行）：**营地系统（商店/营地仓库/工作间/背包渲染，36 函数导出 window.NORTH_CAMP，背包物品行"使用"按钮 v5.4）**——2026-08-17 第五次拆分
- `static/north-data.js`（约 790 行）：纯数据——`window.NORTH_DATA` 含 16 张事件表 TABLES、ITEM_ACTIONS、CHECK_ACTIONS（闭包回调依赖运行期上下文）、**ITEM_USE_TABLE（背包物品使用效果表：药草 1d2/绒蜂蜜 1d4+寒冷抗性3/白花藤 1d4/治疗药水 2d4+2/驱寒药膏，效果与 wp 表对齐；v5.8 起支持状态类效果 cfg.status：松茸→力量/体质检定优势、魔法泉水→智力检定优势）**
- `static/north-survival.js`（约 250 行）：严寒/口粮/迷失/燃料判定层
- `static/north-guild.js`（约 120 行）：等级积分/晋升阶梯可视化
- `static/north-tavern.js`（约 70 行）：酒馆聊天
- `static/north-fx.js`（约 100 行）：特效；`north-expedition.css`（约 1760 行）

## 功能

- **冒险者**：首次进入输入冒险者名，可在公会中随时修改；**冒险者头像（徽章，v5.3）**：面板头部圆形头像（默认🐺），点击上传图片（`POST /api/north/avatar`，登录用户 north_u<id>.<ext> 命名自动清理旧文件，未登录 north_temp 单文件覆盖仅会话内），URL 存 `_advAvatar` 随存档保存（JSON 导入/导出同步）
- **探索中角色锁定（v5.3）**：`canSwitchChar()`——探索深度>0 且未昏迷倒下（`isKnockedDown`）时禁止切换；charSelect 与 campCharSelect 两处 change 监听同步拦截（回滚原值 + 系统日志"🚫 探索中无法切换角色，请先返回营地"）；回到营地（深度归零）或昏迷倒下后解锁
- **事件链探索**：16 张事件表驱动的探索玩法，逐事件推进、检定与奖励
- **营地**：营地管理（背包/口粮/生存物资），系统日志
- **背包与商店**：物品获取/使用（ITEM_ACTIONS）、商店交易
- **🧪 背包物品直接使用（v5.4）**：治疗/驱寒类物品在补给站/铁匠/炼金背包、营地仓库背包、营地角色卡物品行显示"使用"按钮（stopPropagation 防误触出售/转移，仅 ITEM_USE_TABLE 命中渲染）；探索页生存面板"🧪 治疗药水"按钮（满血/无货 disabled）；`useBackpackItem(itemName)` 扣减→掷治疗骰回血→日志→2 秒防抖存档→`refreshBagUseUI` 四步 try-catch 隔离刷新；纯治疗物品满血先于扣减拦截
- **✨ 状态池（v5.8）**：道具使用后的临时状态存入 `statusPool`（[{key,name,source,uses}]，键规则 `adv:<属性>` / `adv:skill:<技能>`，同名叠加、归零整条移除）；`handleStepCheck` 事件检定掷骰前按 step.skill/step.ability 匹配状态 → 掷两次取高（3D 双掷，取消回退单次）→ **检定后 `consumeStatus` 自动移除（无论成败）**；`checkCold` 严寒检定查 `adv:con` 优先于驱寒药膏（不叠加）；生存面板徽章区 ✨ 紫粉展示（.badge-flag.status-pool，含剩余次数）；云存档 `statusPool` + JSON 导出/导入同步；旧存档无字段默认空数组
- **生存判定**：严寒/口粮/迷失/燃料四类判定（checkCold/checkRation 等），与背包双向同步
- **公会**：等级与积分、晋升阶梯（青羽→白羽）、晋升奖励
- **酒馆**：酒馆聊天
- **存档**：自动存（30 秒定时+2 秒防抖）+ 手动多存档槽，纯服务器端；未登录仅会话内生效

## 上下文与数据共享（重要）

- `north-data.js` 首行 `var CTX = window.NORTH_CTX = window.NORTH_CTX || {}` 创建全局
- main.js 末尾用 `Object.defineProperty` 注入 **getter**（activeChar/activeCharId/username/statsData——变量会被重新赋值必须实时读）+ 函数引用（updateSurvivalUI/addSystemLog/runCheckChain 等）
- 其余模块只读 `window.NORTH_CTX`，不直接耦合 main 内部变量
- **营地模块桥**：main.js 内定义 `window.NORTH_CAMP_CTX`（27 个营地状态 getter/setter + 7 个函数引用，含 **useBackpackItem**）；north-camp.js 内全部以 `window.NORTH_CAMP_CTX.xxx` **运行时解析**（不缓存桥引用，加载顺序无关）；营地初始化与 showPopup 包装钩子挂在 DOMContentLoaded **捕获阶段**（先于 main.js 的 init，带 50ms 防御重试）
- **拆分模块必须从 `window.NORTH_CTX` 取运行期函数**，曾有嵌套作用域导致 `normalizeCampStorage is not defined` 的坑

## 存档

- **纯服务器端，无 localStorage**。登录后 30 秒定时 `saveNorthToServer()` + 变更防抖 2 秒自动存 + 手动多存档槽，均走 `/api/north/save`；v5.8 起存档含 `statusPool`（状态池，collectNorthSaveData / exportSave 保存，loadNorthFromServer / importSave 恢复）
- 冒险者名 `_northUsername` 存于存档 `save_data._northName`；未登录仅会话内生效
- **未登录不自动存档为设计如此**（2026-08-24 确认）：仅会话内生效 + 手动 JSON 导出，勿加 localStorage 兜底
- **改名/导入必须"先 load → merge → save"**，防止只写一个字段覆盖整个存档

## API

- `GET /north-expedition`（页面）
- `POST /api/north/save`（{save_name, save_data}，按 user_id+save_name 覆盖更新）
- `GET /api/north/load?save_name=auto`（仅登录用户）
- `GET /api/north/saves`（存档列表）
- `POST /api/north/avatar`（v5.3 冒险者头像上传：multipart 字段 avatar，复用官网头像校验规则 2MB/图片格式，返回 {ok, url}）

## 关键结构

- `north_saves` 表（PG）：user_id / save_name / save_data(JSON 文本) / updated_at
- 等级 `RANK_LEVELS`：青羽0 → 黑羽50 → 蓝羽120 → 银羽220 → 金羽350 → 赤羽520 → 白羽750，晋升奖励 guildPoints 积分
- 生存物资双存储：survival.fuel 与背包 inventory 需 `reconcileSurvivalFuel()` 双向同步

## 修改注意点

- 存档格式容错：campStorage 曾存成 dict 导致 `(inv||[]).map` 崩溃——读取必须经 `normalizeCampStorage()` 规范化，`_invRenderKey` 需 `Array.isArray` 容错；旧缓存会把坏格式写回，需强制刷新
- north-*.js 改版注意模板引用顺序与缓存版本号（如需）
- **物品使用按钮**（v5.4）：按钮 onclick 必须 `event.stopPropagation()`（父行 onclick 是出售/存入仓库）；使用后数量扣减会触发 `_invRenderKey` 变化自动重绘，但 refreshBagUseUI 各步已 try-catch 隔离，勿恢复为顺序裸调用；满血拦截必须在扣减之前（防药水白扣）；效果一律以 wp 物品表为准（霜羽雉的蛋无回血效果，勿加入 ITEM_USE_TABLE）
- **状态池**（v5.8）：状态键格式固定 `adv:con`/`adv:skill:奥秘`，新增状态物品只需在 ITEM_USE_TABLE 加 `status` 数组；`consumeStatus` 调用会触发 addSystemLog（自动 2 秒防抖存档），勿重复手动存档；检定挂接仅 handleStepCheck 与 checkCold 两处，新增检定入口需同步挂接；状态池与 survival.coldResist 并存（旧机制不动，新状态走状态池）
