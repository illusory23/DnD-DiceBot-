- **新手指南（v5.4）**：/guide 静态五章折叠卡片；入口：首页顶栏"帮助"（未登录+登录态均指向 /guide）、页脚"帮助文档"、侧栏、全部 portal 页 navbar

## 数据源（重要）

- 2026-08-15 起全量 PostgreSQL。`_load_json_file(path, default)`（app.py 约 4647 行）是 **PG 查询封装**：path==`_COMMUNITY_FILE` 读 `CommunityPost`，`_WORKSHOP_FILE` 读 `WorkshopItem`；`_save_json_file` 全删全插保留 id
- **收藏仍走 `data/favorites.json`**（`Favorite` 表已有但读取来源仍是 JSON 文件）——收藏的标题/作者必须从 `_load_json_file` 同源读取，勿改查 ORM（曾因来源不一致导致收藏列表为空）

## API

- 社区：`/api/community/boards`、`/api/community/boards/<id>/threads`（q 搜索+分页）、`/api/community/posts`（POST 发帖/GET 列表）、`/api/community/posts/<id>`（详情）、`.../like`、`.../comments`（POST/DELETE）
- 工坊：`/api/workshop/items`（GET/POST）、`/api/workshop/items/<id>`（详情/点赞/评论）
- 其他：`/api/favorites`（GET/POST）、`/api/notifications`、`/api/topics`、`/api/auth/*`（register/login/me/update-profile/avatar）、`/api/online/users`
- 好友（v5.4）：`GET /api/users/search?q=`（用户名精确→模糊 / 纯数字按ID，返回 relation：friend/pending_out/pending_in/none，排除自己）、`POST /api/friends/request`（反向 pending 自动转 accepted 互加）、`POST /api/friends/respond`、`GET /api/friends`（v5.5 起附 unread 私聊未读数；**v5.8 起附 online 在线状态**，复用 `_online_sessions` 按 username 匹配）、`GET /api/friends/pending`、`DELETE /api/friends/<user_id>`；通知复用 `_notify(user_id,...)`（勿用 `_notify_author` 按名查）
- 好友私聊（v5.5）：`GET /api/friends/chat/<friend_id>?since_id=`（增量拉取并自动已读）、`POST /api/friends/chat/<friend_id>`（{content?, image_url?}，image_url 仅允许 /static/ 路径）、`POST /api/friends/chat/<friend_id>/image`（multipart 'image'，复用头像校验 2MB/图片格式，存 `static/chat-images/`）、`GET /api/friends/chat/unread-count`；表 `friend_messages`
- 好友资料（v5.5）：`GET /api/users/<user_id>/profile`（仅好友/本人，返回 avatar_url/id/username/last_login/bio/posts/workshop_items/favorites，无 email/phone/ip）
- 更新日志（v5.3）：`/api/changelog`（文件列表，按 `YYYY-MM-DD_序号_主题.txt` 正则解析，**按 (日期,序号) 数字倒序**）、`/api/changelog/<path:filename>`（单个文件内容，basename+正则防路径穿越，UTF-8 errors='replace'）

## 关键数据结构

- 帖子：id/board/title/content/images/author/created_at/reply_count/comments[{id,username,content,created_at}]/likes[用户名数组]
- 工坊：id/title/desc/file_url/author/created_at/cat/comments/likes
- 通知类型：`post_comment`/`workshop_comment`/`post_like`/`workshop_like`/`post_fav`/`workshop_fav`/`mention`/`friend_request`/`friend_accept`，字段含 group_key（聚合去重）+count
- 好友（v5.4）：`friend_requests` 表（user_id 发起方 / target_id 接收方 / status pending|accepted|rejected / created_at / responded_at，**存 id 不存用户名防改名丢数据**，好友关系 = accepted 记录）

## 修改注意点（已知坑）

- **改名后通知找不到作者**：`_notify_author` 按 username 精确查 User，作者改过名会丢失通知——改名接口已同步更新帖子/工坊 author 字段，历史数据如不一致需人工处理
- 首页导航"🔔 消息通知"入口 + 未读红点（30 秒轮询）；通知列表每 30 秒自动刷新
- 帖子/工坊点击进入独立详情页 `/post/<id>`、`/workshop/<id>`（原先弹窗已改跳转）
- 自己给自己点赞/收藏不通知；同项聚合（group_key）
- **好友表勿学收藏的全删全插模式**：直接 ORM 增删；发通知必须传 user_id（`_notify`），勿走 `_notify_author`
- **首页顶栏"帮助"有两处**：未登录静态 HTML（237 行）与登录后 `updateUserUI` 重写的 header-actions（388 行），两处都要指向 /guide（曾只改前者，登录态仍是空链接）
