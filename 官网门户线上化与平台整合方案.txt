━━━ 一、现状诊断 ━━━

┌──────────────┬──────────────────────────┬────────────────────┐
│     组件     │         当前状态          │        问题        │
├──────────────┼──────────────────────────┼────────────────────┤
│ 骰娘核心     │ Flask，端口5000，20+路由  │ ✅ 已是在线服务    │
│ (web/app.py) │ API 完备                  │                    │
├──────────────┼──────────────────────────┼────────────────────┤
│ 官网门户     │ 本地静态HTML              │ ❌ 不在Flask中     │
│ (官网门户/)  │ file:// 打开              │ 无路由、无法外网访问│
├──────────────┼──────────────────────────┼────────────────────┤
│ 用户系统     │ localStorage 模拟登录     │ ❌ 假的            │
│              │ 无后端验证                │ 刷新即丢失         │
├──────────────┼──────────────────────────┼────────────────────┤
│ 数据库       │ 无                        │ ⚠️ 无用户/帖子    │
│              │ 角色卡用JSON文件存储      │ 工坊持久化         │
└──────────────┴──────────────────────────┴────────────────────┘

核心问题：官网门户和跑团平台物理隔离——门户是本地文件，平台是Flask服务，
它们互相不知道对方存在。

核心思路：把官网门户"搬进"Flask，让它成为 / 路由，然后通过共享数据库和
Session，让门户和跑团应用变成同一个系统的两个入口。

━━━ 四、阶段 0：基础整合（1-2天，立即可做）━━━

目标：官网门户能通过 http://localhost:5000 访问

4.1 操作步骤：

  1. 将 官网门户/index.html 复制到 web/templates/portal/index.html
  2. 分离 CSS 到 static/portal/style.css
  3. 分离 JS 到 static/portal/script.js
  4. 在 app.py 添加路由：
     @app.route('/')
     def index():
         return render_template('portal/index.html')
  5. 添加 test4 路由：
     @app.route('/test4')
     def test4():
         return render_template('test4.html')
  6. 把 file:// 路径全部改为 url_for 或相对路径
  7. 启动：python web/app.py → 访问 http://localhost:5000

4.2 阶段 0 完工后能做什么：

  ✅ 首页展示：核心功能卡片、冒险者酒馆板块列表、创意工坊精选、关于平台
  ✅ 功能介绍页：6大功能卡片 + 详情介绍（含北境召唤卡 → test4）
  ✅ 板块列表点击：展示模拟帖子列表（数据来自JS硬编码数组）
  ✅ 面包屑导航：首页 » 功能介绍 » 详情
  ✅ 创意工坊展示：精选卡片 + 详情
  ✅ 登录/注册弹窗：弹窗正常，但仍基于 localStorage
  ✅ test4 北境雪原：视频背景 + 雪花极光动画 + 品牌标识回跳
  ✅ 页面样式：CSS完整保留
  ✅ 左侧功能栏：展开/收起、导航高亮
  ✅ 多设备可通过局域网访问 http://<IP>:5000

  ❌ 多人访问时数据不互通（各自浏览器的localStorage独立）
  ❌ 注册/登录仍基于localStorage，换设备即丢失
  ❌ 社区无真实发帖/回帖功能
  ❌ 首页卡片点击仍是弹窗，不跳转真实工具页


━━━ 五、阶段 1：数据库 + 用户系统（3-5天）━━━

目标：用户能真正注册/登录，门户和跑团平台共享登录状态

5.1 技术选型：

  后端：
    ORM:      Flask-SQLAlchemy
    密码:     werkzeug.security.generate_password_hash
    会话:     Flask-Login（服务端session）

5.2 数据库表（最小可用集）：

  -- 用户表
  CREATE TABLE users (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      username VARCHAR(64) UNIQUE NOT NULL,
      email VARCHAR(128) UNIQUE NOT NULL,
      password_hash VARCHAR(256) NOT NULL,
      avatar_url VARCHAR(512),
      bio TEXT,
      created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  );

  -- 跑团统计
  CREATE TABLE character_sheets (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      user_id INTEGER REFERENCES users(id),
      name VARCHAR(128),
      data_json TEXT,
      created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  );

  -- 社区帖子
  CREATE TABLE posts (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      board_slug VARCHAR(32),
      user_id INTEGER REFERENCES users(id),
      title VARCHAR(256),
      content TEXT,
      is_pinned BOOLEAN DEFAULT 0,
      created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
      updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  );

  -- 回帖
  CREATE TABLE replies (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      post_id INTEGER REFERENCES posts(id),
      user_id INTEGER REFERENCES users(id),
      content TEXT,
      created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  );

  -- 创意工坊
  CREATE TABLE workshop_items (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      user_id INTEGER REFERENCES users(id),
      title VARCHAR(256),
      category VARCHAR(32),
      description TEXT,
      file_path VARCHAR(512),
      downloads INTEGER DEFAULT 0,
      created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  );

  CREATE TABLE workshop_ratings (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      item_id INTEGER REFERENCES workshop_items(id),
      user_id INTEGER REFERENCES users(id),
      score INTEGER CHECK(score BETWEEN 1 AND 5),
      comment TEXT,
      created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  );

5.3 实施步骤：

  1. 添加 flask-sqlalchemy, flask-login 到 requirements.txt
  2. 创建 web/models.py 定义所有表
  3. 创建 web/auth.py（Blueprint）处理注册/登录/登出
  4. 替换门户中所有 localStorage 模拟登录为真实后端调用
  5. 门户和跑团应用共享 current_user（Flask-Login）

5.4 阶段 1 完工后新增能力：

  ✅ 用户注册 → 写入数据库 → 真实持久化
  ✅ 用户登录 → 服务端验证密码 → Session维持
  ✅ 同一账号在不同浏览器/设备登录
  ✅ 门户和跑团工具共享登录状态
  ✅ 退出登录清除服务端Session


━━━ 六、阶段 2：社区系统（3-5天）━━━

目标：板块列表、发帖/回帖、面包屑导航全部真实化

6.1 Flask蓝图路由：

  /community                  → 冒险者酒馆首页（板块列表）
  /community/board/<slug>     → 板块内帖子列表
  /community/post/<id>        → 帖子详情 + 回复
  /community/post/new         → 发帖编辑器
  /community/search           → 全文搜索

6.2 前端改造：

  1. 面包屑不再硬编码，改为后端传入 breadcrumb 列表
  2. renderBoard() 改为真实 HTTP 请求
  3. 板块统计数据从数据库 COUNT 查询
  4. 发帖/回帖通过表单 POST → 写入数据库 → 刷新列表

6.3 阶段 2 完工后新增能力：

  ✅ 真实发帖 → 存入数据库 → 所有人可见
  ✅ 回帖功能 → 帖子下显示回复列表
  ✅ 板块统计真实化（主题数/帖子数从DB查询）
  ✅ 置顶帖 + 热门/新帖标签
  ✅ 面包屑完整三级路径

━━━ 九、阶段 5：部署上线（2-3天）━━━

9.1 方案A：轻量自托管

  服务器:   阿里云/腾讯云 2C4G VPS
  域名:     chenfengzhijuan.com
  HTTPS:    Let's Encrypt 免费证书
  部署:     Gunicorn + Nginx

9.2 方案B：Docker部署（推荐团队协作）

  docker-compose.yml 服务编排：
    - web       (Flask + Gunicorn)
    - nginx     (反向代理 + 静态资源)
    - db        (PostgreSQL)
    - redis     (Session存储，可选)

9.3 方案C：免费托管

  后端:     Railway / Render（免费额度）
  数据库:   Supabase / PlanetScale（免费额度）
  静态资源: 直接走Flask渲染，不分离部署

9.4 Nginx配置示例：

  server {
      listen 80;
      server_name chenfengzhijuan.com;

      location / {
          proxy_pass http://127.0.0.1:5000;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
      }

      location /static/ {
          alias /path/to/web/static/;
          expires 30d;
      }

      location /uploads/ {
          alias /path/to/web/uploads/;
      }

      client_max_body_size 100M;
  }
