# 角色卡模块

## 文件与职责

- `web/templates/character.html`（约 300 行）：页面骨架（三栏：创建/导入/角色列表 | 角色详情 | 物品搜索），末尾按序引入 `character.js?v=18` + `character-monsters.js?v=15` + `character-features.js?v=16` + `character-inventory.js?v=16`
- `web/static/character.js`（约 1450 行）：前端主逻辑（列表分组拖拽、详情渲染、属性/技能/豁免/法术位/背景/头像、Excel 导入、公开角色只读视图；**v5.9：详情页体型/种族/死亡豁免可编辑**）
- `web/static/character-monsters.js`（约 175 行）：怪物搜索/详情/从怪物创建角色（2026-08-17 拆分；v5.6：搜索词条名一致性检查、点击带 source 版本参数、创建传真实 hp/ac/abilities）
- `web/static/character-features.js`（约 167 行）：特性区渲染与编辑（2026-08-17 拆分）
- `web/static/character-inventory.js`（约 229 行）：武器/物品/钱币编辑 + 物品搜索（2026-08-17 拆分）
- `core/character.py`（约 1150 行）：角色卡业务层（CRUD、属性、技能、豁免、HP、法术位、武器、法术、背景、物品、分组、`import_from_excel_data`）
- `core/models.py`：Character / SpellSlot / PreparedSpell / LearnedSpell / Ability / SkillProficiency / SaveProficiency / CharacterGroup / CharacterFeature
- `web/app.py`：角色相关 API 集中在约 1006-2050 行
- `utils/excel_importer.py`：Excel 角色卡导入（`_detect_version` → v440 / dnd5e24 / neko21 三种模板适配）

## 功能

- **角色管理**：创建、复制、删除角色；分组（创建/重命名/删除/拖拽排序；**v5.6：自建分组中删除角色 = 仅移出分组，角色卡保留在总角色组，总角色组删除才是真删除**；**v5.7：删除/移出分组后折叠状态与滚动位置保持**——loadCharList 按分组 id 合并旧 `_collapsed` 状态，仅新分组默认折叠；removeCharFromGroup 补滚动保存）
- **详情编辑增强（v5.9）**：详情头部种族可点击编辑（editTextFieldFromData，空时显示"未知种族"）；meta 编辑行新增「体型」字段（`characters.size` 列，从怪物创建角色时独立存储，不再拼入 race）；死亡豁免成功/失败次数（0-3）点击编辑 + [稳定]/[未稳定] 点击切换（`editDeathSaveField`/`toggleDeathStable` → `PUT /api/character/<id>/death-saves`，成功后 selectChar 重渲染）
- **属性编辑**：六维属性、技能熟练/专精、豁免（属性+熟练自动计算；**v5.7：18 技能→属性映射统一为全局常量 SKILL_AB_MAP**，编辑渲染/只读渲染/toggleSkill 三处同源，修复自然(误wis)/生存(误求生)/欺诈(误欺瞒)三处错误）
- **战斗数值**：HP（当前/最大/临时）、AC、先攻、速度、HD、被动察觉
- **装备与财产**：武器（攻击加值/伤害骰/伤害类型）、护甲、背包物品（堆叠）、钱币
- **法术**：法术位（每环 已用/最大）、已学法术、准备法术、施法属性/DC/攻击加值
- **背景与特性**：背景（个性/理念/羁绊/缺陷/故事）、职业能力、专长、种族特性、特殊能力
- **头像**：上传/清除（文件命名"角色名_id.ext"防覆盖，URL 时间戳防缓存）
- **Excel 导入**：支持 v4.4.0 / DND5E24（悲灵）/ NekoWorks 三种模板自动识别，含背景/背包/特性等配套 sheet（**v5.7：修复 DND5E24 起源表缺失区域标签导致 range(None) 崩溃**——`_import_origin_sheet` 下一标签未找到时用 start+3 兜底）
- **怪物搜索**：从怪物库搜索并创建角色（**v5.6：创建时使用词条真实 HP/AC/属性——SRD 字段 → 词条文本解析（"AC 11""HP 19（3d8+6）""力量15"）→ CR 估算兜底；HP 按词条"几d几+几"骰子表达式自动投掷生成，前端提示"（HP 按词条 xdX+x 投掷生成）"**）；物品搜索辅助装备录入
- **怪物版本选版**：v5.6 起怪物库含 5e MM2014 与 5r MM25 同名版本，列表行标注来源（MM/MM25…），点击带 source 参数精确打开对应版本词条
- **公开角色**：DM 可切换公开/私有，PL 对公开角色只读查看

## 调用链

- character.js **全部为顶层 script 声明，非 ES 模块**，函数之间直接互相调用，HTML onclick 直接引用（须保持全局作用域，不要改成 module）
- 拆分后的 3 个子模块同为顶层函数声明、全局可见：**无需桥/导出**，HTML 引入顺序主文件在前即可（调用都发生在用户交互时）
- 入口 `loadCharList()`（页面底部调用）→ `refreshCharListDisplay()` → `renderCharListHTML()` / `applyCharListEvents()`（HTML5 拖拽排序）
- 选择角色：`selectChar(id)` → `GET /api/character/<id>` → `POST /api/character/<name>/use` → `renderCharDetail()`（编辑视图）或 `renderCharReadonly()`（DM 公开角色的 PL 只读视图）
- 角色列表为"自己创建 + DM 公开"角色（PL 无用户名时返回空列表）

## 关键 API

- `GET /api/characters?name=&role=`：列角色+分组（DM 全量，PL 按可见性过滤）
- `POST /api/character`：创建
- `GET|PUT|DELETE /api/character/<name_or_id>`：**id 或名字均可**（`_resolve_char` 先试 int 再按名）
- `POST /api/character/<name_or_id>/copy`、`/use`、`/field`（PUT 通用字段，str_fields 含 size）、`/hp`、`/longrest`、`/ability`、`/skill`、`/save-prof`
- **死亡豁免（v5.9）**：`PUT /api/character/<name_or_id>/death-saves`（手动编辑：successes/failures 0-3 + is_stable；failures=3 → is_dead 死亡、<3 → 复活）；`POST /api/character/<name_or_id>/death-save`（掷一次：body roll_value 1-20 + 可选 modifier，规则 1→失败×2、≥10→成功、20→3 成功稳定，失败累计 3 → is_dead=True；已死亡角色不再累计）
- `/spell-slot`、`/spell-slots`（PUT 整体保存）、`/prepared-spell`（POST/DELETE）、`/learned-spell`（POST/DELETE）
- `/weapon`、`/item`、`/inventory/stack`、`/coin`、`/background`（PUT）、`/features/<category>`、`/visibility`（POST，仅 DM）、`/portrait`（GET/PUT/DELETE）、`/portrait/upload`
- `POST /api/character/import`（Excel 导入）、`/from-monster`（v5.6：接收 hp/ac/abilities 真实字段，HP 按词条骰子表达式投掷，返回 hp_dice/hp_rolled）
- 分组：`/api/character-groups`（POST）、`/reorder`、`PUT|DELETE /api/character-groups/<id>`、`PUT /api/character/<id>/group`（**group_id=null 移出分组，v5.6 自建组删除走此接口**）、`POST /api/characters/reorder`

## 关键数据结构

- `characters` 表核心列：id/name/player/created_by/**is_public**/level/**class_（列名 'class'，Python 关键字）**/race/subrace/**size（体型，v5.9）**/alignment/faith/gender/age/height/weight_field/hp_max/hp_current/temp_hp/ac/initiative_bonus/speed/proficiency_bonus/hit_dice/xp/passive_perception/spellcasting_ability/spell_attack_bonus/spell_save_dc/portrait_path/source_file/resistances/key_abilities/sort_order/group_id/user_id
- `_char_to_dict` 输出：
  - `abilities` 键为**英文**（str/dex/con/int/wis/cha），另有扁平 `str` 等字段与 `ability_mods`
  - `skill_proficiencies` 键为**中文技能名**
  - `save_proficiencies` 键为**英文能力名**（前端兼容旧中文键）
  - `spell_slots`：`{环阶字符串: {max, used}}`（**键必须是字符串**）
  - `features` 按英文分类：class_feature / feat / racial_trait / special_ability / other
- Excel 导入：`import_from_excel_data(data)` 接收扁平化字典（含 abilities/save_proficiencies/skill_proficiencies/weapons/spell_slots/prepared_spells/coins/inventory/features）

## 修改注意点（已知坑）

- **set_ability 中文键坑**：`normalize_ability` 返回中文名（如"力量"），写入前必须映射回英文列键再 setattr（智力列名为 `int_score`）；`set_save_proficiency` 统一存英文键并自动迁移旧中文键数据——**新代码勿以中文键写入**
- **int 属性列名是 `int_score`**（`int` 是 Python 关键字）
- **死亡豁免键名与死亡状态（v5.9）**：`_char_to_dict` 输出 `death_saves` 对象（{successes, failures, is_stable, is_dead}），旧键 `ds_successes/ds_failures/ds_stable` 保留兼容其他调用方——新代码统一读 `death_saves` 对象（曾因键名不一致导致详情页豁免恒显 0/0）；`is_dead` 死亡标记（失败 3 次），长休对死亡角色跳过豁免重置，手动编辑失败数 <3 自动复活
- **is_public 公开角色**：PL 对公开角色只读（`renderCharReadonly` 无编辑控件），列表带"🔓 公开"标记且不可拖拽/复制/删除；地图 `canViewCharInfo` 同样受控
- **头像**：文件命名"角色名_id.ext"防覆盖；URL 加 `?t=` 时间戳防缓存；GET portrait 返回 no-cache；上传按钮在头像正下方（曾因 82vh 滚动区被裁掉，勿再移动布局）
- **权限**：`getIdentity()` 读 sessionStorage `dnd_joined_room` 判定 DM/PL，勿改该存储格式
- **缓存版本号**：改 character.js 或任一子模块必须同步 character.html 中 4 个脚本的 `?v=N` 版本号（当前 character.js v18 / character-monsters.js v15 / character-features.js v16 / character-inventory.js v16，2026-08-25 已升）
- 后端 `make_server` 无热重载，改后端代码需重启服务
- 页面不依赖 3D 骰子（角色卡未引入 dice3d）
