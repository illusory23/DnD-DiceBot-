二、可行性结论: ✅ 可行，但需分阶段实施
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  总体评估：用 Vue 3 + TypeScript 重构前端是可行的，且长期收益显著。

  关键制约因素：
    ① 后端 Flask API（113个端点）结构良好，无需修改即可作为 Vue 前端的数据源
    ② 3D 骰子引擎（dice-engine-v3）是纯 JS 库，可在 Vue 中通过 ref + onMounted 封装
    ③ 战术地图（map.js）是 Canvas 2D 绘图，需要适配 Vue 生命周期但逻辑可保留
    ④ 北境雪原（north-expedition.html）是最复杂的迁移目标，建议最后处理

  不建议一次性重写（Big Bang），推荐「绞杀者模式」(Strangler Fig) 渐进迁移。

3.3  部署模式

  方案A（推荐）: 前后端分离
    - Flask 仅作为 API 服务器 (:5000)
    - Vite 开发服务器 (:5173) → 开发时代理 API 到 Flask
    - 生产构建: Vue 打包为静态文件，Flask 直接 serve (或 nginx)

  方案B: 嵌入模式
    - Vue 打包后放到 web/static/vue-dist/
    - Flask 增加 catch-all 路由 serve index.html
    - 适合不想改变部署方式的场景

八、不做 Vue 的替代方案
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  如果评估后认为全量 Vue 迁移成本过高，以下替代方案也可显著改善现状：

  方案A: 渐进增强（成本最低，2-3天）
    • 将现有 HTML 的 <style> 和 <script> 提取到独立 CSS/JS 文件
    • JS 模块化：用 ES modules (import/export) 拆分超大文件
    • 不引入框架，不改变技术栈

  方案B: Alpine.js + HTMX（成本中等，1-2周）
    • 保留现有 HTML 结构，用 Alpine.js 添加响应式
    • 用 HTMX 替代 fetch() 调用，减少手动 AJAX 代码
    • 不需要构建工具，直接在现有 Flask 模板中使用

  方案C: Petite-Vue（成本低，3-5天）
    • Vue 3 的轻量子集（6KB），适用于渐进增强
    • 在现有 HTML 中直接使用 Vue 模板语法
    • 不需要构建工具，逐步迁移
